# Beginner guide — Decision Register

The **Decision Register** tracks outstanding questions and the decisions those questions become. Each item stays tied to one Epic, Feature, or Task.

A question and the decision it becomes are the same record. Promoting a question keeps that record and changes its kind to Decision.

**Related:** [Plan hierarchy](faq:plan-hierarchy) · [Risk Register](faq:risk-register)

---

## Who can use this?

| Role | What you can do |
| --- | --- |
| **View** | Read the register, including the source quote |
| **Contributor** | Add and update items |
| **Administrator** | Archive an item, and must give a reason |

---

## Concepts in one minute

| Term | Meaning |
| --- | --- |
| **Question** | Something the team still needs answered. |
| **Decision** | The choice a question became. It records an outcome and a rationale. |
| **Outstanding** | Still open. This is the list you see first. |
| **Resolved** | Answered or decided; kept so you can read it later. |
| **Duplicate** | The same topic as another item. It points at the surviving item. |
| **Archive** | Removed from the working list. An administrator must give a reason. |
| **Type 1** | A decision that is hard to undo. |
| **Type 2** | A decision that can be reversed. |
| **Blocks the work** | This outstanding item is in the way of the linked Epic, Feature, or Task. |

Type 1 and Type 2 apply to decisions. They record who decided and when.

---

## Open the Decision Register

1. Select the project in the sidebar.
2. Choose **Decision Register** (it sits after **Project Plan**).
3. You can also open it from the home tiles for that project.

The home list is a filterable register. It is not a board.

Header counts show how many items are outstanding, overdue, and blocking. **Assigned to me** lists outstanding items assigned to you, with overdue items first.

---

## Read an item

1. Open a row.
2. Read the statement, who raised it, who it is assigned to, the target date, and whether it blocks the linked work.
3. Read the source, including the quote, when one was recorded.
4. A duplicate names the surviving item. Follow that pointer instead of treating the duplicate as a second decision.

---

## Add or update an item (contributor)

1. Add a question or a decision from the register, or from the plan edit screen for that Epic, Feature, or Task.
2. Update the statement, assignees, target date, and whether it blocks the linked work.
3. When a question is answered by a choice, turn it into a decision on the same item. Record who decided, and whether it is Type 1 or Type 2.
4. Mark a repeat as **Duplicate** and point it at the item that remains.

---

## Archive an item (administrator)

1. Open the item.
2. Choose **Archive**.
3. Enter a reason. The register will not archive the item without one.

---

## On the plan edit screen

The edit screen for a linked Epic, Feature, or Task shows a count of register items for that work.

It also shows a warning when an outstanding item blocks that work. Use the count to open the register and resolve or update the item.

---

## What this screen does not do

- There are no email alerts.
- There is no suggestion inbox yet. Nothing is added from a transcript until a later slice, and only after a person accepts it.

---

## Common mistakes

| Mistake | Fix |
| --- | --- |
| Looked for decisions on the Project Plan page | Open **Decision Register** in the sidebar. The plan edit screen only shows a count and a blocking warning |
| Expected a duplicate to stand on its own | Open the surviving item the duplicate points at |
| Cannot archive | Ask an administrator, and include the reason you want recorded |
| Waited for an email when a target date passed | Check the register. Overdue items are marked there; there is no email alert |
