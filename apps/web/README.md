# Web

Vite and React. Sign-in uses the Cognito user pool from the dev stack. The browser keeps that session, so a refresh stays signed in. The app sends the ID token. API Gateway checks that token. The dev pool accepts email and password. Set `VITE_MFA_REQUIRED=true` only for a build whose pool requires an authenticator.

An administrator can open and change every project. A Contributor can edit, add, and upload on the projects they can open. View can open those same screens and cannot change them. The members list and the invite form set that access. The API refuses a View change even if a button is shown.

Overview stores health and notes. Documents uploads a file through a short-lived S3 URL, keeps older versions, and restores a soft-deleted file without replacing the current version. New folder creates a folder in the current location, including an empty one. A file can be moved into a folder that already exists. Each file can carry a vault source label (`compass-upload`, `krisp`, `fireflies`, or `other`). A file without a label stays out of the staff vault.

A Compass project (`recordSource` is `compass`) opens a full issue editor for title, description, status, issue type, parent, estimate, dates, iteration, milestone, priority, labels, assignees, comments, dependencies, and other relationships. Those saves stay in Compass. The Sync from GitHub button is hidden. An administrator edits that project's status, iterations, labels, issue types, priorities, and milestones in Settings, under Catalog. A label or issue type can use one of ten theme colors. The label color outlines its tag in the issue editor. The issue type color fills that issue's bar on the timeline. A GitHub project keeps the shorter editor that writes back to GitHub.

Plan and Kanban read the GitHub projection. The plan is grouped by Epic. A Feature sits under an Epic, an Issue sits under a Feature or an Epic, and a Sub-issue sits under an Issue. The Workstream issue number is saved with the GitHub mapping and is not a row. Add Epic, Add Feature, Add Task, and Add Sub-issue create that GitHub issue and parent link. A new Epic uses issue type EPIC, a new Feature uses Feature, and a new Task uses Task. A Sub-issue is created with no type. The add drawer sends the same GitHub fields as the edit drawer for that type. An Epic or Feature can keep its own Start and Finish until a task or sub-issue is added under it. Then those dates come from the tasks. Tasks with no Epic stay in Outside an Epic. The Kanban board stays grouped by status. Each plan row can change the title, status, and effort; the save is sent to GitHub. Dragging a Kanban card onto another column sends that column name as the status. The Kanban pencil opens that same editor in the shared drawer. The drawer heading is the issue title. Description is the GitHub issue body. The drawer shows the first 200 characters until it is expanded. A GitHub sub-issue is indented under its parent on the Timeline. That parent becomes Done only when every task under it is Done. The Timeline bar uses the Start and Finish fields. Each Timeline row shows that issue's GitHub status. Clicking that status opens the same GitHub issue editor as the Kanban pencil. That drawer also sets the GitHub iteration, assignee, and comments. Choosing an iteration copies its start and end into Start and Finish. A later iteration keeps Start and sets Finish to the new end date. The dates can still be changed by hand. A comment is stored in the GitHub Comments field with the One80Compass user and the date. A dependency is a GitHub blocked-by link. The later task starts the day after the earlier one finishes. If a date change would break that, the plan shows the moves and waits for approval. An administrator sets Baseline 1 from the current tasks, including tasks that have no dates. Later baselines are proposed and then approved or rejected. Comparison marks a task as newly scheduled, added after the baseline, or removed since the baseline. A milestone can be confirmed once every task on it is Done. Reopening that confirmation requires an explanation. The target date is the GitHub due date. The forecast is the latest finish date when every task on the milestone has one. Progress counts leaf issues and treats a missing estimate as 1 without writing that 1 back to GitHub. A manual override requires an explanation. The GitHub App credentials stay on the Lambdas.

Status reports move from draft to review, approval, and publish. Each publish keeps a separate copy. Starting a revision edits a new draft and does not change a published copy. An administrator can draft from the vault with a question; the draft cites filed sources and does not change the live plan. The layout preview for that control is `/dev/layout/reports`.

Audit lists the newest recorded changes for the customer, including who made the change and the prior and new values. It is always in the navigation once a project is selected.

`EditDrawer` in `src/ui.tsx` is the shared right-hand editor for members and plan issues. Its body scrolls, and Save stays on the left of the footer with Cancel on the right. An X in the upper right closes the drawer. The X, Cancel, Escape, and the backdrop close immediately when nothing has changed. If a field differs from the values opened with the drawer, a warning offers Save changes, Close without saving, or Keep editing. `EditRowButton` is the pencil control for the last cell of a table row.

Copy the stack outputs into `apps/web/.env.local`:

```
VITE_USER_POOL_ID=
VITE_USER_POOL_CLIENT_ID=
VITE_API_URL=
```

Then run `npm run dev -w @one80compass/web` and open `http://localhost:5173`.

`npm run deploy:dev` publishes the same build to CloudFront. Open the `SiteUrl` output from the dev stack. The API allows both that address and localhost.
